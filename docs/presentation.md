# แนวทางสาธิต “สิ้นเดือนยังมีข้าว”

## อธิบายโปรเจกต์สั้น ๆ

เว็บนี้ช่วยนักศึกษาเลือกร้านอาหารในงบของตัวเอง โดยเก็บร้าน เมนูแนะนำ ราคา คะแนน และรีวิวส่วนตัวไว้ในฐานข้อมูล SQLite ผู้ใช้เพิ่ม แก้ไข ลบ ค้นหา และสุ่มร้านได้ โดย Backend จะกรองราคาให้ไม่เกินงบก่อนสุ่ม

## ลำดับสาธิตประมาณ 3–5 นาที

1. เปิดหน้าเว็บ แนะนำปัญหา “คิดไม่ออกว่าจะกินอะไร และมีงบจำกัด”
2. เลือกงบ 50 บาทแล้วสุ่มร้าน อธิบายราคาและเงินเหลือ
3. กรองประเภทอาหารหรือค้นหาเมนู แล้วสุ่มอีกครั้ง
4. เพิ่มร้านตัวอย่างของตนเอง 1 ร้าน พร้อมราคา คะแนน และรีวิว
5. แก้รีวิว รีเฟรช แล้วแสดงว่าข้อมูลยังอยู่
6. เปิด `/debug.html` กดเรียก API อีกครั้ง เพื่อดู JSON จาก Backend และ SQLite
7. ลบร้านทดสอบ และแสดงกล่องยืนยันก่อนลบ

## ไฟล์ที่ควรอ่านให้เข้าใจก่อนนำเสนอ

- `public/index.html`: โครงหน้าเว็บและแบบฟอร์ม
- `public/app.js`: `loadRestaurants()` อ่านข้อมูล, `api()` ส่ง request, ฟอร์มส่ง POST/PUT, ปุ่มลบส่ง DELETE
- `server/index.js`: จัดการ endpoint, ตรวจข้อมูลด้วย `validate()`, กรองร้านด้วย `filtered()`
- `server/database.js`: สร้าง SQLite ตาราง restaurants และเติมข้อมูลสาธิตเฉพาะครั้งแรก
- `server/seed.js`: รายการร้านสมมติเริ่มต้น

## คำถามที่อาจเจอ

**Resource หลักคืออะไร?** ร้านอาหาร (`restaurants`) หนึ่งร้านมีหนึ่งเมนูแนะนำ หนึ่งคะแนน และหนึ่งรีวิวส่วนตัว

**Frontend กับ Backend ต่างกันอย่างไร?** Frontend แสดงผลและรับข้อมูลจากผู้ใช้ ส่วน Backend ตรวจข้อมูลและอ่าน/เขียนฐานข้อมูล แล้วส่ง JSON กลับ

**ฐานข้อมูลอยู่ที่ไหน?** ไฟล์ `data/restaurants.sqlite` ของเครื่องที่รันเซิร์ฟเวอร์ ไม่ได้เก็บเฉพาะในหน้าเว็บหรือ localStorage

**สุ่มอย่างไรไม่ให้เกินงบ?** ใช้เงื่อนไข SQL `price <= budget` กรองร่วมกับประเภท/คำค้น แล้วใช้ `randomInt` เลือกหนึ่งรายการจากร้านที่ผ่านเงื่อนไข

**ทำไมกดสุ่มแล้วได้ร้านเดิม?** การสุ่มแต่ละครั้งเป็นอิสระกัน และถ้ามีร้านตรงเงื่อนไขเพียงร้านเดียวก็จะได้ร้านนั้นทุกครั้ง

**ถ้าไม่มีร้านในงบทำอย่างไร?** API ส่งสถานะ 404 พร้อมข้อความ หน้าเว็บแจ้งให้เพิ่มงบหรือเปลี่ยนตัวกรอง

**คะแนนเป็นค่าเฉลี่ยหรือไม่?** ไม่ใช่ เป็นคะแนนส่วนตัว 1–5 ดาว เหมาะกับขอบเขต mini project

**ป้องกันข้อมูลผิดอย่างไร?** ตรวจทั้งฟอร์มและ Backend เช่น ราคาต้องเป็นบวก คะแนนเป็นจำนวนเต็ม 1–5 และข้อความต้องไม่เกินความยาวที่กำหนด

**ข้อมูลร้านเป็นของจริงไหม?** รายการเริ่มต้นเป็นข้อมูลสาธิตที่ติดป้ายชัดเจน ผู้ใช้สามารถเพิ่มร้านจริงได้เอง

**ทำไมไม่ต้องมี host?** โจทย์กำหนดให้รันบนเครื่องได้ และส่ง source code พร้อม README ผ่าน GitHub
